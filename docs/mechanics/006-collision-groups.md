# Collision groups and single-hit resolution

- Mechanic: Five fixed collision groups in which any hit resolves exactly once, routed through one scoring path (SYS-03).
- Derived behavior: The reference resolves each interaction by marking the struck object's state to *hit* in the contact frame, and all scoring flows through one path, so nothing can double-score. Five groups exist and no others: player shots vs air enemies; bombs vs ground objects; enemy shots vs the player; air enemies vs the player; Bacura vs the player.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `check_solvalou_hit`, `check_flying_enemies_shot`, `handle_bombed_obj_and_award_points`. The five groups and the exhaustive exception-verdict table are recorded in [core game systems](../spec/core-game-systems.md) (SYS-03), which delegates every enemy-side verdict (Bacura bounce, bomb-vs-Bacura, shot-vs-ground, Andor Genesis core, hidden Sol Tower / Bonus Flag) to the aerial-enemies, ground-objects, Andor Genesis, and secrets documents; this record cites that home and does not restate the verdicts.
- Transfer class: General behavior (collision-group structure and the single-hit invariant; no source text or media copied).
- Scratch interpretation: A single resolution path — the warp `resolve hit` block marks the struck slot's `slot state` to HIT (2) exactly once and calls the one `score` hook, so a hit can never double-score. The struck slot is named by `hit slot`, which the per-group **detector** sets. This slice builds only that single-hit path and declares the five groups (the `COLLISION_GROUPS` constant, each an attacker-range × victim-range over the recorded slot ranges); the per-group overlap detection that would set `hit slot` and call `resolve hit` is **delegated to the slices that add the participants**, exactly as the spec delegates the verdicts. `score` is the single scoring hook, empty until ECO-01.
- Scratch evidence: The `resolve hit` and `score` warp custom blocks and the `hit slot` Stage variable in `tools/game_director.py` (`install_resolve_hit`, `install_score`); the `COLLISION_GROUPS` constant with its five (attacker, victim) range pairs; structural and negative-fixture checks in `tests/test_scratch_project.py` (`_sys03_failures`, `test_collision_groups_match_spec`).
- Acceptance criteria: Exactly one slot-state→HIT write exists and it is in `resolve hit`; exactly one `score` call exists (the single scoring path); both blocks are defined; `COLLISION_GROUPS` is the five recorded groups over the correct slot ranges; the negative fixtures prove the checks redden (a second `score` call; a resolver that skips the HIT write); two clean builds stay byte-identical and survive the round-trip.
