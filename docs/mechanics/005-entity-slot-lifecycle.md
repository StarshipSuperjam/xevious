# Entity slot lifecycle

- Mechanic: A fixed array of 64 object slots — the shared vocabulary every enemy, projectile, target, and effect will occupy (SYS-02).
- Derived behavior: The reference runs 64 fixed object slots walked in ascending index order each frame; empty slots are skipped; every entity passes idle → active → hit → idle within its slot, and a slot frees with no leaked state. This slice lays the slot array and its reset-clear; the walk that dispatches it is record 005's central-loop section and the entity occupants are later slices.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `main_fn_2__handle_objects` (4745-4798), `add_obj_handler` (4801-4815), `check_scroll_offscreen` (4826-4839). The slot ranges and their binding capacities are recorded in [player craft and weapons](../spec/player-craft-and-weapons.md) (their normative home) and in [core game systems](../spec/core-game-systems.md) (SYS-02); this record cites them and does not restate the numbers.
- Transfer class: General behavior and numeric constant (slot ranges/capacities are reference-derived; no source text or media copied).
- Scratch interpretation: The 64 slots are two parallel fixed-length Stage lists — `slot type` (0 = empty, skipped by the walk) and `slot state` (0 idle / 1 active / 2 hit) — where arcade object slot `0xNN` is Scratch list index `NN+1` (lists are 1-based). The per-slot position and age fields the reference also carries are **not built this slice**: with the sprite→slot position mirror deferred (see record 006 / the plan), nothing authors positions yet, so those fields land with the first entity that authors them centrally (the enemy slice). A warp (atomic) `clear slots` custom block resets both lists to empty/idle and runs on every `director reset` — all reset scopes clear transient gameplay.
- Scratch evidence: Stage lists `slot type` and `slot state` (64 zeros each) and the `slot index` loop cursor variable; the `clear slots` warp custom block and its call in the Stage `director reset` receiver in `tools/game_director.py` (`install_clear_slots`); the range/capacity constants (`SLOT_COUNT`, `SHOT_SLOTS`, `FLYING_SLOTS`, …) with their dual arcade-hex ↔ list-index columns; structural and negative-fixture checks in `tests/test_scratch_project.py` (`_sys02_slot_failures`, `test_slot_ranges_match_capacities`).
- Acceptance criteria: The Stage carries `slot type` and `slot state` lists of exactly 64 zeros; a warp `clear slots` block exists and is invoked from a `director reset` receiver; the generator constants reproduce the recorded ranges (ground 16, Bacura 16, shots 3, bullets 19, flying 6) and the `0xNN ↔ NN+1` mapping; the negative fixtures prove each check reddens (a length-63 list, an un-warped clear, a dropped clear call); two clean builds stay byte-identical and survive the round-trip.
- Fidelity status: **Dormant machinery, foundation-only.** The slot array and its reset-clear exist and are structurally verified, but no entity occupies a slot yet except the player shots in the next commit's cap; the walk that dispatches slots (record 006 central-loop section) and every enemy/bullet/ground/Bacura occupant are later slices. Position/age fields are deferred to their first author. The operator-facing "entities never leak across a long session" acceptance is not exercisable this slice (nothing to leak beyond the shot alloc/free) and is deferred to the first slice with live occupants.
- License status: The pinned reference repository states no reusable license; no reference source text or media was copied.
- Known deviations or uncertainty: The `slot x` / `slot y` / `slot age` fields the reference record carries are intentionally unbuilt until a consumer authors positions centrally (the sprite→slot mirror is deferred to avoid a cross-thread nondeterminism seam; see the plan-review dispositions). Crater persistence, boss-part slot occupancy (Andor Genesis ground slots 1-15), and the off-screen cull margin are recorded in the spec and built with the entities that need them.
