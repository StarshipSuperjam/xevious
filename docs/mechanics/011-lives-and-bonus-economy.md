# Lives and bonus economy — starting craft, bonus thresholds, and the cap quirk

- Mechanic: ECO-03 lives economy — a DIP-selected number of starting craft, and bonus craft granted as the score passes a per-setting threshold that then advances by a per-setting increment, including the arcade's at-cap grant quirk.
- Derived behavior: A new game starts with the configured number of craft. After every point award, if bonuses are enabled the score is checked against the current threshold; crossing it grants one craft, plays the extend cue, and advances the threshold by the setting's increment. A disabled setting never grants. Once the score is pinned at 9,999,990 the threshold can no longer exceed it, so every further award grants a craft.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `check_for_extra_solvalou` (109-183, incl. the 114-118 at-cap region), `starting_solvalou_tbl` (1174-1175), `first_bonus_life_tbls` (1179-1199), `bonus_tbl_ptrs` (1854-1877). Every starting count, first threshold, and repeat increment — per setting — is committed, BCD-decoded, in [docs/spec/data/scores.json](../spec/data/scores.json) (`starting_lives`, `first_bonus_thresholds`, `repeat_bonus_increments`) and recorded in the settled [scoring, lives, and game over](../spec/scoring-lives-and-game-over.md) document (ECO-03).
- Transfer class: General behavior, numeric constant, and structured table.
- Scratch interpretation: The Stage `check bonus life` warp block (called by `score` after each award) runs only when the threshold sentinel is non-zero (bonuses enabled); at the pinned cap it grants every award, otherwise it grants once when `score` reaches `next bonus` and advances `next bonus` by the repeat increment. A grant is `change craft by 1`, the `extend` sound, and a `craft changed` broadcast (the HUD refresh signal, consumed by the HUD commit). On a world reset (`cold-start`/`new-game`) `craft` and `next bonus` are seeded by reading the ingested DIP tables at the default index, so the committed data is the single source of truth. Both bonus table pairs (the 1/2/3-lives pair and the 5-lives pair) and the starting-lives table are ingested as Stage lists.
- Scratch evidence: `install_check_bonus_life`, the DIP constants and the `STARTING_LIVES`/`FIRST_BONUS_*`/`REPEAT_BONUS_*` data, the `craft`/`next bonus` variables, and the reset seeds in `tools/game_director.py`; the `craft changed` broadcast; the ingested `starting lives`/`first bonus 123`/`first bonus 5`/`repeat bonus 123`/`repeat bonus 5` lists in `src/xevious/project.json`. Contract and negative-fixture checks in `tests/test_scratch_project.py`: `_eco03_failures` (enabled guard, cap quirk, threshold grant + advance, the craft/sound/signal, and the DIP seeds) with its eight negatives, `test_bonus_and_lives_data_match_scores_json` (the five tables equal `scores.json` under the null→sentinel mapping), and the extended Stage-variable / write-forbid guards.
- Acceptance criteria: The generated starting-lives and bonus tables equal `scores.json` (engine); the check runs after every award and only when enabled (engine, structural). Pressing the debug **S** fixture to reach 20,000 grants an extra craft with its sound, and running past 9,999,990 grants a craft on every award (operator, via the fixture). Verifying the non-default DIP settings in play needs a DIP selector, which is not wired this slice (see deviations).
- Fidelity status: The disable setting, the normal repeating thresholds, and the cap quirk are implemented and operator-verifiable at the default DIP. Starting craft = 3, first bonus 20,000, then every 60,000 (the default DIP). No score or craft count persists to disk (EX-05 excluded).
- License status: The pinned reference states no reusable license; only derived numeric values (the starting-lives, threshold, and increment tables) are committed, each cited to `scores.json`, and no reference source text or media was reproduced.
- Known deviations or uncertainty: **DIP defaults are a project choice** — the raw-index-to-physical-switch mapping is unrecorded upstream (`starting_lives` note), so starting index 3 (→3 craft) and bonus index 0 (→first 20,000, repeat 60,000) are chosen and recorded here, with arcade observation as the resolution path. The **123-vs-5 table selection** carries the reference's own recorded inconsistency (its two selection sites disagree; the build follows the repeat-award site, per the spec) — fixed to the 1/2/3-lives pair at the default DIP. The **stop-after-two setting is deferred**: the committed data pins the disable sentinel but not which DIP index stops after the second bonus life (`check_for_extra_solvalou` describes it behaviorally without a committed index), so it is not wired to a specific setting this slice — the default DIP does not hit it, and pinning the index needs a reference/arcade pass. Bonuses beyond the default DIP setting are not operator-selectable until a DIP selector exists.
