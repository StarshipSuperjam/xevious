# Andor Genesis core: bomb path, scoring, and destruction

- Mechanic: The only path that destroys and scores the Andor Genesis boss — bombing the core awards 4,000 points plus the documented shell-slot leftover-value bug, bursts the core in place and converts it into the up-flying Bragza, cascades the surviving gun ports without scoring them, and runs a distinct destroyed departure (colour flash, then the wreck scrolls off with the screen) that tears the composite down. An unbombed boss instead leaves on its schedule (the BOSS-01 departure). Gun-port firing, armor immunity, individual-port scoring, and the Bragza flight cadence are the companion mechanic (BOSS-02, [047](047-andor-defenses.md)).
- Derived behavior: The core (obj slot 14, type 0x4A) is a normal bombable ground target: it is born `_STATE=2`, carries `_PTS=60` (4,000 points), and sits on the master's cell. When a bomb lands on it, the shared bomb router sets it `_STATE=3` and awards 4,000. Because the invisible master object (obj slot 15) is forced `_STATE=2` at spawn but its `_PTS` is **never initialized**, and it shares the core's cell, the same bomb also awards the master's stale `_PTS` — whatever the previous tenant of slot 15 left behind (the reference's own comment above `handle_4B` gives Area 9 an extra 200 points from a Zolbak). This shell-slot leftover-value award is a preserved arcade bug. Once the core is `_STATE=3`, its handler runs its own explosion in place until the explosion state finishes (`_STATE==4`), and only then converts the core slot into Bragza: it sets a vertical up velocity (`_dX=0xffd0`), zeroes the horizontal velocity, and sets `_STATE=8` (neither the bomb router's `_STATE==2` nor zapper fodder, so Bragza is indestructible). Meanwhile the master's handler, whose very first instruction each frame tests the core for `_STATE==3`, branches to the destroyed animation the moment the core is bombed — even mid-descent, before the hold. The gun-port cascade is **per-port, not master-driven**: each port's own handler polls the core (`cmp #3,(core _STATE); jeq <xx>_gun_port_hit`, 5523/5574/5625/5676) **before** its fire call and routes itself to its explosion tail — awarding **nothing** for the cascade. Crucially the cascaded port stays `_STATE=2` (active) throughout that explosion (only `gun_port_explosion_finished`, 5721, sets `_STATE=4`), so a bomb landing on it mid-burst still scores its 1,000; a port scores its 1,000 whenever directly bombed, cascading or not. The destroyed animation sets the shared colour to `0x1d`, and after a short timer to `6` (a flash), then sinks the wreck **downward off the bottom** with twice the screen scroll (`_X += -2·scroll_delta`; `scroll_delta` is negative here, so `_X` **increases** toward the removal row MSB `0x30`, which sits **below** the hold row MSB `0x10`) until it reaches that removal row, at which point the master clears only its own state and type. This is the opposite direction from the scripted `andor_genesis_leave` retreat, which *decreases* `_X` up off the top toward MSB `0xf8`. The armor plates self-clear when the master goes inactive; the ports have already exploded; the converted core is now the independent Bragza — so the departure never frees Bragza's slot.

- Scratch interpretation: `_ground_seed_andor` seeds the core `SLOT_ACTIVE` with `slot pts` = the 1-based `VALUE_TABLE_POINTS` position for 4,000 (offset 60), and seeds the master `SLOT_ACTIVE` with its `slot pts` **left un-seeded** so it carries the previous slot tenant's value (the shell bug). Each tick `update andor master` pins the master's own slot onto the shared anchor (the core's cell), so the shared `install_check_ground_hit` detector — which already scores only `SLOT_ACTIVE` on-target slots by `slot pts` — awards both the core (4,000) and the stale master value on one core bomb. On core `SLOT_HIT`, `update andor master` (which dispatches last) only flashes `andor genesis colour` to `0x1d` and latches an `andor destroyed timer` so the flash + departure fire exactly once — it **does not flip the port states**. The gun-port cascade lives per-port in `update andor part`, mirroring the arcade's per-port core poll: a port's explosion trigger is an `operator_or` — it explodes when directly bombed (`SLOT_HIT`), **or** it is a port and the core slot is `SLOT_HIT` (the cascade), **or** its own explosion clock is already running (`slot timer > 0`). A core-cascaded port therefore explodes while **staying `SLOT_ACTIVE`** (still bombable for its 1,000 through the `SLOT_ACTIVE`-gated detector — the C4 master-flip model wrongly made it un-bombable and let it fire one extra volley on the death frame; both are now source-exact, [047](047-andor-defenses.md) DH-1). The explode branch advances `slot timer` so the shared ground-destroy burst animates, and on a finished burst resolves type-aware: the core flips to `ANDOR_BRAGZA_TYPE` stamped with the `ANDOR_ARMOR_IMMUNE` sentinel (blocking any second bomb from re-scoring the stale pts), while a port frees its slot. The renderer shows the burst for a mortal boss part on `SLOT_HIT` **or** `slot timer > 0` (an Andor-only render seam), so a cascaded ACTIVE port draws its explosion rather than its idle muzzle. `update andor bragza` then flies the converted core up-screen (`slot x -= ANDOR_BRAGZA_STEP`, 4-frame costume) and culls it off the top. The master's teardown is **type-aware** — it frees only slots still holding an armor/port/core/master type, never the `ANDOR_BRAGZA_TYPE` slot — so a still-flying Bragza is never clobbered.

- Known deviations or uncertainty: (1) **Burst-then-convert timing is approximate.** The arcade converts the core to Bragza when its own `gun_port_explosion` reaches explosion state `_STATE==4`; the port converts when its shared 8-frame ground-destroy burst completes (`floor(slot timer / burst step) >= EXPLODE_COSTUME_COUNT`), so the burst-then-convert **ordering** is faithful while the exact frame count is the port's shared-burst convention. (2) **Flash duration is approximate**: the arcade holds colour `0x1d` for a 3-frame `_TIMER` before switching to `6`; the port holds the flash for its tick-rebased equivalent, a brief cosmetic flash rather than a frame-exact reproduction. (3) **The destroyed departure is a distinct animation from the scripted leave.** The BOSS-01 scheduled departure (`andor_genesis_leave`) retreats upward; the destruction departure (`andor_genesis_destroyed`) is a flash then a scroll-off with the screen — the port models it as a separate destroyed sub-state, not the leave path. (4) **A mid-descent core bomb legitimately ends the boss.** The master's first instruction polls the core state every frame, so bombing the core before the hold ends the encounter; the BOSS-01 phase comment that assumed the end flag only rises after hold was stale and has been corrected — the source wins. (5) **Colour is a documented port interpretation**, as in BOSS-01/BOSS-02: the arcade indexes a hardware palette byte, and the port maps the stepped index onto a Scratch `color` graphic effect. (6) The arcade plays explosion and boss sounds during destruction; the port emits no sound (audio is a separate slice). (7) **Teardown consolidation**: the arcade's parts self-remove as the master clears; the port's master teardown explicitly frees the armor/port/core/master slots while deliberately never freeing the converted Bragza slot, reaching an identical clean end state.
