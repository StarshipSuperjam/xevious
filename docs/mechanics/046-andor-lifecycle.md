# Andor Genesis boss lifecycle

- Mechanic: The Andor Genesis mothership's lifecycle — its scripted arrival descent, fixed screen hold, per-frame composite alignment of all fifteen parts, the shared colour-cycle on every visible part, the core's flip-orientation animation, and the scripted upward departure. Combat (gun-port firing, armor immunity, core bomb/destruction, Bragza, the destruction cascade) is deliberately out of scope this slice.
- Derived behavior: When a live area schedule (areas 4/9/14) or the ground debug key fires the start opcode, the arcade stands the boss up as a fifteen-part composite around one invisible master object: the master is armed at obj slot 15 with `_X` starting at cell −8 (MSB `0xf8`) and lateral `_Y = 0x0e80`, then a loop stamps the fourteen visible parts (nine armor plates 0x41–0x49, four gun ports 0x4F–0x52, one core 0x4A) into obj slots 1–14. Each frame the master adds `+0x20` to `_X` until it reaches cell +16 (MSB `0x10`), then holds that screen row without scrolling; every part reads the master's position and adds its own fixed composite offset, so the whole octagon moves rigidly. A shared colour byte steps through an eight-entry triangle table `[2,3,4,5,6,5,4,3]` indexed by `(countup_timer_1 >> 3) & 7`, and every visible part copies it into `_COLOUR` each frame, so armor, ports, and core pulse in unison. The core additionally rewrites `_ATTR = 0x80 | ((countup_timer_1 >> 3) & 0x0c)` each frame, animating its two flip bits. When the end flag is set (by the schedule's end opcode), the master retreats `−0x10` per frame back to cell −8 and then tears the composite down. No reward is given for a departure; the destruction path is a separate mechanic (slice 16).
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_sub.68k`: `sub_2_fn_20__andor_genesis_start` (544–564) arms the master at obj slot 15 (`_X` MSB `0xf8`, `_Y=0x0e80`, `_STATE=2`, invisible `_CODE`) and loops the fourteen visible parts into obj slots 1–14; `andor_genesis_data` (565–566) is the fifteen-byte part-type table; `sub_2_fn_21__andor_genesis_end` (569–572) sets `andor_genesis_end_flag`. `src/xevious_main.68k`: `handle_4B_Andor_Genesis_obj_15` (5386–5406) is the master descend-then-hold state machine (`+0x20` to MSB `0x10`, no scroll add at hold, checks the end flag); `andor_genesis_leave` (5426–5438) retreats `−0x10` per frame to MSB `0xf8`; `remove_andor_genesis` (5440–5443) clears the master; `handle_4A_Andor_Genesis_obj_14` (5447–5468) is the core, fixed `_CODE=0x10`, per-frame `_ATTR=0x80|((countup_timer_1>>3)&0x0c)` and `_COLOUR` copy; `cycle_andor_genesis_colour` (5758–5764) advances the shared colour byte from `andor_genesis_colour_tbl` (5766–5767) at `(countup_timer_1>>3)&7`; `handle_41_Andor_Genesis_obj_09` through `handle_49_Andor_Genesis_obj_01` (5771–5983) are the nine armor plates with their composite offsets and `_COLOUR` copies; `handle_4F_Andor_Genesis_obj_13` through `handle_52_Andor_Genesis_obj_10` (5508–5687) are the four corner gun ports with their offsets and `_COLOUR` copies (their fire path is slice 16).
- Transfer class: Behavioral port and numeric constant (instruction-derived control flow — the descend/hold/leave state machine, the per-part composite offsets, the colour-cycle index, and the core flip cadence — plus the derived part-offset tables; no source text, ROM, or media copied this record).
- Scratch interpretation: The ordered walk `advance slots` (SYS-04) dispatches the master-typed slot to an update proc that runs the descend→hold→leave→teardown state machine over shared stage variables `andor master x` / `andor master y`, and each part-typed slot to an update proc that sets its `slot x`/`slot y` to the master's shared position plus a per-type composite offset read from two owned lists (`andor part depth`, `andor part lateral`). The colour cycle is a shared variable stepped from the tick counter; the shared ground render pool (GND-08) draws each boss slot by `slot type`, applying a `color` graphic effect scaled by a fixed port constant to realize the arcade colour pulse, and selecting the core costume by its flip phase. The master occupies Scratch slot 16 and dispatches last in the ascending walk, so parts follow the master with a uniform one-frame lag that is zero at hold and cosmetically invisible.
- Scratch evidence: Update procs `update andor master` and `update andor part`, the walk dispatch branches on the master and part types, the arm/seed and end-flag schedule branches, and the render `families` branches (armor / ports / core-with-flip, each pulsing colour; every non-boss arm clears the colour effect) in `src/xevious/project.json` (regenerated); owned variables `andor master x` / `andor master y` and owned lists `andor part depth` / `andor part lateral` in `src/xevious/runtime_identifiers.json`; `tests/test_scratch_project.py` (the `_boss01_failures` structural guards for arrival, part-to-master alignment, layout equality against `andor-genesis.json`, departure, and colour-clear-on-non-boss, each with a biting negative; the regenerated `.sb3` build-hash pin); harness scenarios `boss-arrives-and-holds`, `boss-parts-align-to-master`, `boss-departs-on-end-flag`, `boss-band-isolation`, and `non-boss-clone-has-no-residual-tint` in `harness/lib/catalog.js`, each with a biting negative mutation.
- Acceptance criteria: The built `.sb3` loads headless; when summoned (live area schedule or the existing ground debug key) the boss descends from off the top edge to a fixed hold row and stops adding scroll; all fifteen parts stay rigidly aligned to the master at their `andor-genesis.json` offsets while it moves; armor, ports, and core pulse colour in unison and the core also cycles its flip orientation; on the end flag the composite retreats upward off-screen and every boss slot is freed with no reward; earlier ground families are untouched and a clone that previously drew a boss part shows no residual tint on the next normal ground object; and two generator runs are byte-identical (build-hash pinned).
- Fidelity status: BOSS-01 is **partial** (lifecycle only) — the arrival, hold, composite alignment, colour cycle, core flip animation, and departure are built and verified line-by-line against the pinned reference this slice; gun-port firing, armor hit-immunity, the core bomb/destruction path, Bragza, and the destruction cascade are deliberately deferred to slice 16 (BOSS-02/BOSS-03).
- License status: No new reference or media transfer this record; the Andor part costumes are the credited crops recorded in `src/xevious/assets/provenance.json` (delivered in this PR's art commit), and the derived core flip variants are recorded there as deterministic H/V flips of the credited core crop.
- Known deviations or uncertainty: (1) Core flip is a **documented port interpretation**. The arcade sets the core's `_ATTR` flip bits every frame, but the reference's NeoGeo sprite renderer applies flip only to 2×2 sprites and ignores it on the 1×1 core, so the flip is not observable in that reference build; the port realizes the Namco arcade intent as a four-costume (none/x/y/xy) cycle selected by `(tick>>4)&3`, a deliberate divergence from the reference's observable render, kept by operator decision. (2) Colour is a **documented port interpretation**: the arcade indexes a hardware palette byte; the port maps the same stepped index onto a Scratch `color` graphic effect scaled by a fixed constant, which approximates rather than reproduces the arcade palette. (3) **Part teardown consolidation**: in the arcade the parts self-remove when the master's state clears, entangled with the destruction cascade; the port's master teardown instead explicitly frees all fifteen part slots on departure, reaching an identical clean end state without the slice-16 cascade. (4) The arcade plays the Andor Genesis sound each frame; the port emits no sound (audio is a separate slice). (5) Corner-part left/right composite offsets were read from the source handlers, not pixel-measured against a live capture; the operator pixel-verifies the assembled composite at playtest.
