# Credits, coin input, and the one-player start gate

- Mechanic: CAB-02 (one-player facet) — the cabinet's coin economy and credit-gated one-player start: inserting a coin banks one credit up to a ceiling of 99, and a one-player start consumes one credit and is refused when none are banked (no free play). The two-player start facet (`CAB-02.two-player`) and two-player alternation (CAB-03) are deferred to slice 18 (`cabinet.two-player`); the coin **sound** is deferred pending the operator's provenance decision. This record covers the one-player credit/coin/start path delivered this slice.
- Derived behavior: The arcade reads coins and the start buttons together in a single NAMCO-chip-replacement routine. On a coin insert it adds one credit to the credit bank as a BCD add, capped at 0x99 — at the ceiling both the add and the coin sound are skipped — and plays the coin sound. A one-player start is honored only when at least one credit is banked; when honored it deducts one credit and begins a real game, and with zero credits it is ignored. Credits are cabinet economy state: they survive game-over and a new game, and are cleared only at power-on.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`. `src/xevious_sub.68k`: `sub_fn_4__handle_credits_and_start` (171–206) is the coin-and-start routine — it adds one credit per coin (BCD `abcd`) capped at 0x99, plays `COIN_SND` on a successful insert (181), and starts one player only when a credit is available, deducting one; there is no free-play branch. `src/xevious_main.68k`: `main_thread_main_loop` (348–357) shows credits gate entry to a real game — with no credits banked (349–355) the boot path enters the attract cycle instead of a game.
- Transfer class: Behavioral port and numeric constant (instruction-derived control flow — the one-coin-one-credit add, the 0x99 ceiling, the credit-gated deduct-on-start, and the no-free-play rule; no source text, ROM, or media copied this record).
- Scratch interpretation: A `credits` Stage variable holds the 0–99 credit bank (a plain integer, the decimal display of the arcade BCD ceiling); it is initialized to 0 at green flag, is in no reset scope (so it survives game-over and new-game and clears only on power-on), and is classified as economy state in the one-Stage-owned-transition guard. Because there is no coin-box hardware in this port, a keyboard key inserts a coin — the `C` key, a port necessity exactly like the debug summon keys stand in for hardware the port lacks — and the existing start key (Space) is now credit-gated. An always-on Stage green-flag `forever` loop calls a warp `cabinet coin poll` custom block every tick (coins must register in every state — title, best-five, and the demo — while the ordered walk runs only while `playing`); the poll mirrors the P-key debug toggle's rising-edge pattern, so it adds one credit on the tick `C` is first pressed (not every tick it is held) and only while below the cap. The credited-start gate wraps the `title → ready` hat in `if credits > 0` and prepends `change credits by −1`, so a start at zero credits stays on the title. The coin poll also raises a one-tick `coin edge` flag that the non-warp Stage loop reads to run the attract coin-abort (documented in CAB-01), kept out of the warp poll because the transition procedure does a nesting-unsafe `broadcast and wait`.
- Scratch evidence: The `credits` Stage variable (economy), the `coin key held` and `coin edge` machinery variables, the `cabinet coin poll` warp proc and the always-on Stage coin loop, and the `credits > 0` gate with the `change credits by −1` decrement on the `title → ready` path — all in `src/xevious/project.json` (regenerated), with owned identifiers in `src/xevious/runtime_identifiers.json`. `tests/test_game_director.py` classifies `credits` as economy and the coin machinery vars as machinery in the one-Stage-owned-transition-path guard; `tests/test_scratch_project.py` carries the regenerated `.sb3` build-hash pin. Harness scenario `credits-and-1p-start` in `harness/lib/catalog.js` (repeated coins cap at 99; Space at zero credits stays on the title; Space at ≥1 credit decrements and starts the game) with biting negative mutations, and `harness/lib/build.js`'s `reachPlaying` helper now banks a credit before tapping Space so every start-a-game scenario passes the gate.
- Acceptance criteria: Inserting coins raises the credit count one per coin and never past 99; a one-player start with no credits banked is ignored and leaves the cabinet on the title; a start with at least one credit banked deducts exactly one credit and begins a real game; credits persist across game-over and a new game and reset only at power-on; and two generator runs are byte-identical (build-hash pinned). (`credit`, recorded in `assets/game-sounds/manifest.json` and `docs/ASSET_CREDITS.md`). It plays only when a coin

banked credit has lifted the attract mute. With both starts and the coin sound built, **CAB-02 is present**.
