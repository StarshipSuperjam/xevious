# Editor script layout — readable scripts and fully loading sprites in the Scratch editor

- Mechanic: Non-gameplay migration of how the project opens in the Scratch 3 editor. (1) Every sprite's scripts are placed in one column, in reading order, with the editor's own "Clean up Blocks" gap between them, worked out from each script's real drawn height so no script runs into the next. Before, the generator placed each script 150 units below the one before whatever its height, and 148 pairs of scripts overlapped. Reading order puts where a sprite starts running first (green flag, then key presses), then what it responds to (message receivers, grouped by message), then clone starts, then the custom-block definitions the rest call; before, the Stage's green-flag scripts sat below all 76 of its definitions. (2) A cap block is one with no notch underneath, so nothing can attach below it: `delete this clone`, `forever`, or `stop` all / this script. Nineteen scripts had a block chained under `delete this clone`. The game ran them fine, but the editor refuses to build a block under a cap and abandons the rest of that sprite's workspace, so 18 sprites opened in the editor with scripts missing.
- Derived behavior: No arcade behavior changes, and the game runs exactly the same blocks in the same order. Script positions on the code canvas change, and so does how the 19 receiver tails are arranged, but not what they do. In the 18 `director stop` receivers, the `hide` after the delete, and in the blaster's `director reset` receiver, the reload reset and `hide` after it, now follow an always-true `if <1 = 1>` whose mouth ends with `delete this clone`. A clone is deleted inside the `if`; the original sprite, which `delete this clone` passes over, carries on after the `if` exactly as it carried on after the bare delete. An `if` never yields, so the original runs the rest in the same pass. A clone is still visible when it is deleted, so its removal still asks the player for a redraw. scratch-vm asks for one when a visible clone is deleted, but neither when one is hidden nor when a hidden one is deleted, so moving `hide` above the delete (this PR's first approach) would have changed how many passes the player runs in that frame. The order the runtime starts scripts in is the order of the blocks in the file, which positions do not touch.
- Reference provenance: Non-gameplay; no arcade source is involved. The heights follow the Scratch 3 editor's block renderer, scratch-blocks 1.3.0: `core/block_render_svg_vertical.js` (`renderCompute_`, `computeInputHeight_`, `renderDrawRight_`, `renderDrawBottom_`, `renderDefineBlock_`, `getHeightWidth`). The gap follows `core/workspace_svg.js` (`cleanUp`), and the cap rule follows `blocks_vertical/control.js` (`control_stop`'s `hasnext` mutation). The redraw rule is scratch-vm 5.0.300 `src/sprites/rendered-target.js` (`setVisible`, `dispose`) with `src/engine/sequencer.js` (`stepThreads`), the same VM the editor and the harness use, through which the heights were measured.
- Transfer class: Non-gameplay migration.
- Scratch interpretation: A new game-agnostic module, `tools/script_layout.py`, holds an explicit table of how each opcode is drawn and refuses any opcode it does not know. It computes each script's height the way the renderer does and stacks the scripts in reading order at x 0, each 48 units below the one above. `tools/game_director.py` calls it once over every target at the end of `expected_project`, and `Blocks` no longer tracks positions. `Blocks` also refuses to chain any block under a cap, so the editor-load defect cannot come back. Because that check reads the same table, an opcode missing from it is refused as soon as the generator chains it, with a message naming it. `delete_clone_then` builds the always-true `if` wherever something must follow a delete. `tools/script_layout_measure.py` with its page `tools/script_layout_measure.html` repeats the editor measurement for the fixture or for any sb3; its docstring has the steps.
- Scratch evidence: `tools/script_layout.py`; `tools/script_layout_measure.py`; `delete_clone_then` and its two callers in `tools/game_director.py`: `common_stop`, which makes the 18 `director stop` receivers (blaster, start_screen, hud, toroid, enemy_bullet, terrazi, kapi, torkan, zoshi, jara, zakato, giddo-spario, brag-spario, garu-zakato, bacura, sheonite, bonus-flag, ground), and the blaster's `director reset` receiver. `tests/test_script_layout.py` checks the model block by block against `tests/fixtures/script_layout_editor_measurements.json`: sample scripts covering every opcode in the table plus the edge cases, measured in scratch-blocks 1.3.0. It also checks that every shipped sprite is laid out by the model in reading order, that no two scripts overlap, that nothing is chained under a cap, and that no receiver hides a clone before deleting it. The build hash is re-pinned in `tests/test_scratch_project.py`.
- Acceptance criteria: Opening `dist/Xevious.sb3` in the Scratch 3 editor shows every sprite with all of its scripts, in one column, none overlapping, each canvas starting from where that sprite starts running. In the editor's own renderer, every sprite loaded with every block present and each script sat exactly 48 units below the one above it. All 12,762 drawn blocks of the build, with the samples sprite, measured exactly the model's height, and the editor's Clean up left the layout where it was. Gameplay is unchanged: the full pytest suite, the full runtime harness and the release soak pass on this build.
- Fidelity status: Non-gameplay.
- License status: No reference media or code is transferred. scratch-blocks (Apache-2.0) is downloaded by whoever runs the measuring tool, and is read and run only to measure block heights. None of it is copied into the project.
- Known deviations or uncertainty: The model is exact for scratch-blocks 1.3.0, the renderer behind scratch.mit.edu's Scratch 3 editor. A future renderer with different block geometry could draw scripts taller or shorter. The 48-unit gap leaves room for a hat's 16-unit curve, but it is not a guarantee against a different renderer; `tools/script_layout_measure.py` would show the difference. Editing scripts in the editor and then saving keeps whatever positions the editor holds. One column is long on a busy canvas: the Stage's runs to about 179,000 units, its green flags first and its definitions from about y 20,000 down.
