# Editor script layout — readable scripts and fully loading sprites in the Scratch editor

- Mechanic: Non-gameplay migration of how the project opens in the Scratch 3 editor. (1) Every sprite's scripts are placed in one column with the editor's own "Clean up Blocks" gap between them, from each script's real drawn height, so no script runs into the next. Before, the generator placed each script 150 units below the one before whatever its height, and 148 pairs of scripts overlapped. (2) Nineteen scripts had a block chained under `delete this clone`. The game ran them fine, but the editor refuses to build a block under a cap block and abandons the rest of that sprite's workspace, so 18 sprites opened in the editor with scripts missing. Those blocks now run before the delete.
- Derived behavior: No arcade behavior changes. Only script positions on the code canvas and the order of two short receiver tails change. In the 18 `director stop` receivers, `hide` now runs before `delete this clone`, not after it. In the blaster's `director reset` receiver, the reload reset and `hide` now run before it. A clone is deleted at the end of the same script either way, and the original sprite, which `delete this clone` never deletes, runs exactly the same blocks in the same frame. A clone setting its own copy of the sprite-local `blaster reload` just before it is deleted touches no other sprite's state.
- Reference provenance: Non-gameplay; no arcade source is involved. The heights follow the Scratch 3 editor's block renderer, scratch-blocks 1.3.0: `core/block_render_svg_vertical.js` (`renderCompute_`, `computeInputHeight_`, `renderDrawRight_`, `renderDrawBottom_`, `renderDefineBlock_`, `getHeightWidth`). The gap follows `core/workspace_svg.js` (`cleanUp`), and the cap rule follows `blocks_vertical/control.js` (`control_stop`'s `hasnext` mutation). They were measured through scratch-vm 5.0.300, the same VM the editor and the harness use.
- Transfer class: Non-gameplay migration.
- Scratch interpretation: A new game-agnostic module, `tools/script_layout.py`, holds an explicit table of how each opcode is drawn and refuses any opcode it does not know. It computes each script's height the way the renderer does and stacks the scripts in generation order at x 0, each 48 units below the one above. `tools/game_director.py` calls it once over every target at the end of `expected_project`, and `Blocks` no longer tracks positions. `Blocks` also refuses to chain any block under a cap (`delete this clone`, `forever`, or `stop` all / this script), so the editor-load defect cannot come back. `common_stop` and the blaster reset receiver end on the delete.
- Scratch evidence: `tools/script_layout.py`; the 18 `director stop` receivers made by `common_stop` (blaster, start_screen, hud, toroid, enemy_bullet, terrazi, kapi, torkan, zoshi, jara, zakato, giddo-spario, brag-spario, garu-zakato, bacura, sheonite, bonus-flag, ground) and the blaster's `director reset` receiver. `tests/test_script_layout.py` checks the model block by block against `tests/fixtures/script_layout_editor_measurements.json`: sample scripts covering every opcode in the table plus the edge cases, measured in scratch-blocks 1.3.0. It also checks that every shipped sprite is laid out by the model, that no two scripts overlap, and that nothing is chained under a cap. The build hash is re-pinned in `tests/test_scratch_project.py`.
- Acceptance criteria: Opening `dist/Xevious.sb3` in the Scratch 3 editor shows every sprite with all of its scripts, in one column, none overlapping. In the editor's own renderer, all 192 scripts across all sprites loaded with every block present, and each sat exactly 48 units below the one above it. All 12,631 drawn blocks of the shipped build measured exactly the model's height. Gameplay is unchanged: the full pytest suite, the full runtime harness and the release soak pass on this build.
- Fidelity status: Non-gameplay.
- License status: No reference media or code is transferred. scratch-blocks (Apache-2.0) was only read and run to measure block heights; none of it is copied into the project.
- Known deviations or uncertainty: The model is exact for scratch-blocks 1.3.0, the renderer behind scratch.mit.edu's Scratch 3 editor. A future renderer with different block geometry could draw scripts taller or shorter. The 48-unit gap leaves room for a hat's 16-unit curve, but it is not a guarantee against a different renderer. Editing scripts in the editor and then saving keeps whatever positions the editor holds. The fixture's measurements were taken once by hand in a browser page, and its `method` field records how to repeat them.
