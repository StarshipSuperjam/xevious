# Game over — the GAME OVER hold, its glyph text, and the best-five check

- Mechanic: ECO-04 game over — losing the last craft holds a "GAME OVER" message for 128 frames before the cabinet returns to attract, and the final score is checked against the best-five table first.
- Derived behavior: When no craft remain, the game shows GAME OVER, holds it for 128 frames (~2.1 s), then returns to the title/attract flow. Before that return, the final score is checked against the five-entry best-five table: a score at or past fifth place qualifies. The game-over routing is now built (ECO-04 high-score route): a qualifying score is ranked into the live table and the player is routed to the initials-entry screen, while a non-qualifying game returns straight to the attract flow; in a two-player game each qualifying player enters in turn. The initials-entry screen itself is recorded under CAB-04 ([052](052-cabinet-high-scores.md)).
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `check_for_high_score` (1618-1672), `game_over` (549-591, the 128-frame hold). The five default best-five scores (40,000 down to 20,000) are committed, BCD-decoded, in [docs/spec/data/scores.json](../spec/data/scores.json) (`high_score_defaults`) and recorded in the settled [scoring, lives, and game over](../spec/scoring-lives-and-game-over.md) document (ECO-04), which also settles the initials-entry deferral to [cabinet flow](../spec/cabinet-flow.md).
- Transfer class: General behavior and numeric/structured table.
- Scratch interpretation: `solv_death`'s `game-over` branch now holds `GAME_OVER_HOLD_TICKS` (64 ticks = 128 arcade frames) via an empty `hold_ticks` repeat, guarded exactly like the death explosion above it — the hold itself runs unconditionally, but the `if_epoch_state`/`DEATH_EPOCH_ID` check right before the broadcast means a superseding transition (which bumps the shared epoch) cancels a stale hold, so `game over complete` is never sent outside the guard. The `hud` sprite spells "GAME OVER" from its glyph costumes as eight centered costume-clones (role `HUD_ROLE_GAME_OVER_GLYPH`, distinct from every other HUD clone role), spawned only while `game state` is `game-over`, fully unrolled like the existing "HIGH SCORE" label row so no runtime index variable is needed; the shared `director stop` clone-clear retires them on the next transition, same as every other HUD clone. The Stage's `game over complete` receiver computes `qualified` with a `>=` fifth-place test (`score` not below `high score table item 5`, OR — in a two-player game — `other score` not below it) and then **branches on the verdict (ECO-04 high-score route)**: a qualifying current player is ranked into the live table (`rank in`, name left blank) with `entry score`/`entry player`/`entry row` seeded and the one-shot `entry recheck` flag armed to `two player`, and control transitions to the new `high-score-entry` state; a non-qualifying game raises `attract` and transitions to `title`/`cold-start` (which is when `score` itself resets). On entry finish the other player is re-checked against the now-updated fifth place and, if they qualify, the entry screen re-arms for them through the `high-score-entry -> high-score-entry` self-edge, so both players enter in turn. The `high score table` list is ingested from `scores.json`'s `high_score_defaults.scores`; `qualified` is a Stage-only-write variable, reset to 0 on every cold-start/new-game world reset.
