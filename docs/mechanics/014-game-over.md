# Game over — the GAME OVER hold, its glyph text, and the best-five check

- Mechanic: ECO-04 game over — losing the last craft holds a "GAME OVER" message for 128 frames before the cabinet returns to attract, and the final score is checked against the best-five table first.
- Derived behavior: When no craft remain, the final score is checked against the five-entry best-five table the instant the game ends — BEFORE any GAME OVER message. A score at or past fifth place qualifies (`>=`, a tie places). The game-over routing is built (ECO-04 high-score route): a qualifying score is ranked into the live table and the player is routed to the initials-entry screen FIRST; a non-qualifying game skips entry. Either way — once entry is done, or immediately for a non-qualifier — the game then shows GAME OVER, holds it for 128 frames (~2.1 s), and returns to the title/attract flow. In a two-player both-out each qualifying player enters in turn before that hold. The initials-entry screen itself is recorded under CAB-04 ([052](052-cabinet-high-scores.md)).

- Transfer class: General behavior and numeric/structured table.
- Scratch interpretation: the best-five check + routing run at the DEATH decision, not at the hold. The Stage's `death complete` receiver, on the terminal (no-craft, no-alternate) branch, runs `_game_over_route`: it computes `qualified` with a `>=` fifth-place test (`score` not below `high score table item 5`, OR — in a two-player both-out — `other score` not below it) and **branches on the verdict (ECO-04 high-score route)** — a qualifying current player is ranked into the live table (`rank in`, name left blank) with `entry score`/`entry player`/`entry row` seeded and the one-shot `entry recheck` flag armed to `two player`, then control transitions `player-dead -> high-score-entry`; a non-qualifying game records the `game-over` death outcome and transitions `player-dead -> game-over`. The `game-over` state is now a **terminal hold**: `solv_death`'s `game-over` branch holds `GAME_OVER_HOLD_TICKS` (64 ticks = 128 arcade frames) via an empty `hold_ticks` repeat, guarded exactly like the death explosion above it — the hold itself runs unconditionally, but the `if_epoch_state`/`DEATH_EPOCH_ID` check right before the broadcast means a superseding transition (which bumps the shared epoch) cancels a stale hold, so `game over complete` is never sent outside the guard. The Stage's `game over complete` receiver is terminal — it raises `attract` and transitions `game-over -> title`/`cold-start` (which is when `score` itself resets); it does NO best-five work, because that already ran at the death decision. On entry finish (`_high_score_finish`) the entry screen leaves via `high-score-entry -> game-over`, so the GAME OVER hold runs AFTER name entry (faithful to `name_entry_finished -> game_over`, `:1757-1769`); when a second player was armed (`entry recheck`) they are re-checked against the now-updated fifth place and, if they qualify, the entry screen re-arms for them through the `high-score-entry -> high-score-entry` self-edge, so both players enter in turn before the hold. The `hud` sprite spells "GAME OVER" from its glyph costumes as eight centered costume-clones (role `HUD_ROLE_GAME_OVER_GLYPH`, distinct from every other HUD clone role), spawned only while `game state` is `game-over`, fully unrolled like the existing "HIGH SCORE" label row so no runtime index variable is needed; the shared `director stop` clone-clear retires them on the next transition, same as every other HUD clone. The `high score table` list is ingested from `scores.json`'s `high_score_defaults.scores`; `qualified` is a Stage-only-write variable, reset to 0 on every cold-start/new-game world reset.
