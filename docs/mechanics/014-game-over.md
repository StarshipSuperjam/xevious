# Game over — the GAME OVER hold, its glyph text, and the best-five check

- Mechanic: ECO-04 game over — losing the last craft holds a "GAME OVER" message for 128 frames before the cabinet returns to attract, and the final score is checked against the best-five table first.
- Derived behavior: When no craft remain, the game shows GAME OVER, holds it for 128 frames (~2.1 s), then returns to the title/attract flow. Before that return, the final score is checked against the five-entry best-five table: a score that beats fifth place qualifies (the arcade would then show the initials-entry screen; a non-qualifying score returns straight to GAME OVER). This slice records the verdict; it does not build the initials screen.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `check_for_high_score` (1618-1672), `game_over` (549-591, the 128-frame hold). The five default best-five scores (40,000 down to 20,000) are committed, BCD-decoded, in [docs/spec/data/scores.json](../spec/data/scores.json) (`high_score_defaults`) and recorded in the settled [scoring, lives, and game over](../spec/scoring-lives-and-game-over.md) document (ECO-04), which also settles the initials-entry deferral to [cabinet flow](../spec/cabinet-flow.md).
- Transfer class: General behavior and numeric/structured table.
- Scratch interpretation: `solv_death`'s `game-over` branch now holds `GAME_OVER_HOLD_TICKS` (64 ticks = 128 arcade frames) via an empty `hold_ticks` repeat, guarded exactly like the death explosion above it — the hold itself runs unconditionally, but the `if_epoch_state`/`DEATH_EPOCH_ID` check right before the broadcast means a superseding transition (which bumps the shared epoch) cancels a stale hold, so `game over complete` is never sent outside the guard. The `hud` sprite spells "GAME OVER" from its glyph costumes as eight centered costume-clones (role `HUD_ROLE_GAME_OVER_GLYPH`, distinct from every other HUD clone role), spawned only while `game state` is `game-over`, fully unrolled like the existing "HIGH SCORE" label row so no runtime index variable is needed; the shared `director stop` clone-clear retires them on the next transition, same as every other HUD clone. The Stage's `game over complete` receiver computes `qualified` — `score > high score table item 5` — before calling the transition back to `title`/`cold-start` (which is when `score` itself resets), then still shows GAME OVER and returns to title on both a qualifying and a non-qualifying score. The `high score table` list is ingested from `scores.json`'s `high_score_defaults.scores`; `qualified` is a Stage-only-write variable, reset to 0 on every cold-start/new-game world reset.
