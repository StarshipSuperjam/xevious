# Scoring path — award, high score, and the 9,999,990 cap

- Mechanic: ECO-01 single scoring path — an object's point value is added to the score through one route that also tracks the running high score and pins the score at the arcade ceiling.
- Derived behavior: Every point award adds the object's recorded value to the current score, holds the score at 9,999,990 once reached, raises the running high score whenever the score passes it, and runs the bonus-life check after each award. All scoring flows through this one path, so nothing can double-count or bypass the cap.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; `src/xevious_main.68k`: `add_to_score` (64-78), the high-score update (80-107), `set_score_to_9999990` (1836-1840); the object value table `object_value_tbl`/`pts_10000` (data). The 22 decoded point values are committed, BCD-decoded, in [docs/spec/data/scores.json](../spec/data/scores.json) (`master_value_table`); the 9,999,990 ceiling and the 40,000 default top high score are recorded there and in the settled [scoring, lives, and game over](../spec/scoring-lives-and-game-over.md) document (ECO-01).
- Transfer class: General behavior, numeric constant, and structured table.
- Scratch interpretation: The Stage owns one `score` warp custom block that adds `award value` to `score`, clamps `score` to 9,999,990, sets `high score` to `score` when `score` exceeds it, then calls `check bonus life` (the grant itself lands with ECO-03). `award value` is a machinery seam — the resolved point value, set by the collision detector a later slice wires (parallel to `hit slot`); the enemy slice (8) resolves it from the `value table` list, whose position i (1-based) holds `master_value_table.entries[i-1].points`. A debug **S** fixture sets `award value` from the value table and runs `score` this slice, so the economy is operator-verifiable before an enemy awards points. `score` restarts every new game; `high score` is the running best — restored to the 40,000 default only at cold start.
- Scratch evidence: `install_score` and the `install_check_bonus_life` stub, the **S** scoring-fixture hat, and the `value table` list plus the `score`/`high score`/`award value` variables in `tools/game_director.py`; the economy seeds in the Stage `director reset` receiver (score on cold-start/new-game, high score at cold-start only); deterministic generation into `src/xevious/project.json`. Contract and negative-fixture checks in `tests/test_scratch_project.py`: `_eco01_failures` (award→score, cap, high-score track, bonus-check tail, no `change score by` bypass) with its five negatives, `test_value_table_matches_scores_json`, `test_scoring_fixture_drives_the_single_path`, and the extended Stage-variable-set / allowed-proccode / sprite-write-forbid guard.
- Acceptance criteria: The generated `value table` equals `scores.json`'s `master_value_table` points (engine); all scoring routes through the one `score` proc and nothing increments `score` outside it (engine, structural); pressing **S** while playing makes the score climb and the high score track it, the score holds at 9,999,990, and the bonus-life award fires at the configured threshold (operator, via the debug fixture — the bonus grant itself is ECO-03). Destroying a real enemy to award its value is slice 8.
