# Shared ground-renderer clone pool

- Mechanic: Non-gameplay migration collapsing the ten per-family ground render targets into one shared clone pool, with the necessary consolidation of ground z-order into a single layer.
- Derived behavior: Ground installations used to be drawn by ten separate Scratch targets (barra, sol-tower, garu, logram, zolbak, derota, garu derota, boza, grobda, domogram), each spawning sixteen persistent clones — one per ground slot — at director entry. That is 160 live clones against scratch-vm's hard 300-clone ceiling, leaving no room for a boss that occupies fifteen ground slots at once. The migration replaces those ten targets with one shared `ground` target whose sixteen clones each read their slot's live type and switch to that family's costume, so the whole ground band now costs sixteen clones instead of 160. What each ground family looks like and does is unchanged; the only observable change is depth ordering (see deviations), because ten targets that each carried their own layer now render at one layer.
- Reference provenance: Canonical project artifact for a non-gameplay migration — `src/xevious/project.json` (regenerated) and `src/xevious/runtime_identifiers.json`; render architecture in `docs/architecture.md`.
- Transfer class: Non-gameplay migration.
- Scratch interpretation: The per-family costume-selection sub-trees are merged into one `slot type` dispatch inside the shared clone loop — the same multiplex idiom already used within the Boza and Garu families, promoted from `slot state`/`slot link` to `slot type`. The ten families' costume lists are concatenated into one 129-costume list on the shared target; each family's index-based `switch to costume` expression is rebased by that family's offset into the combined list, while by-name costume switches continue to resolve to the first matching (canonical) costume.
- Scratch evidence: Target `ground` in `src/xevious/project.json` (129 costumes, `layerOrder` 27, `currentCostume` 0, variable `ground clone slot`); the removed per-family targets and their per-family clone-slot scopes in `src/xevious/runtime_identifiers.json`, replaced by a single `ground` scope with `ground-clone-slot`; `tests/test_scratch_project.py` (target count 33, the regenerated `.sb3` build-hash pin, and `test_ground_pool_costume_list_is_merge_safe`); harness scenarios `ground-pool-is-one-shared-clone-band` and `ground-pool-dispatches-costume-by-slot-type` in `harness/lib/catalog.js`, each with a biting negative mutation.
- Acceptance criteria: The built `.sb3` loads headless; exactly sixteen `ground` clones exist during play and no legacy per-family ground clones remain; each active, visible ground clone shows a costume drawn from its slot type's family; the live clone total drops by roughly 144, restoring headroom below the 300 ceiling; and two generator runs are byte-identical (build-hash pinned).
- Fidelity status: Non-gameplay migration. The forced z-order consolidation is a partial, arcade-directed correction — see deviations.
- License status: No new reference or media transfer; all costumes are the previously credited ground-family crops carried over unchanged, recorded in `src/xevious/assets/provenance.json`.
- Known deviations or uncertainty: Ten ground targets each had their own `layerOrder` (25, 26, 27, 34, 35, 36, 37, 38, 39, 40), assigned by the accident of the order families were added slice by slice — nothing in the tests, harness, or spec ever pinned that ordering. One shared target has one layer, so all ground now draws at `layerOrder` 27. This moves ground toward Xevious's back-to-front order (terrain, then ground, then aerial enemies, then Solvalou): the seven families that previously drew in front of the aerial enemies at layers 28–33 (zolbak, derota, garu derota, boza, grobda, domogram, sol-tower) now correctly draw behind them. It is only a partial correction: ground at layer 27 still draws in front of the six low-layer aerial families (toroid 18, terrazi 20, kapi 21, torkan 22, zoshi 23, jara 24) and in front of Solvalou (13). Those inversions are a pre-existing, project-wide `layerOrder` build-order artifact (Solvalou itself sits behind the aerial band); putting ground behind all aerial enemies would require renumbering non-ground targets, which is out of scope for this render-only migration and is flagged to the operator. Inter-family overlap ordering among ground objects also collapses to one layer, but ground slots occupy distinct positions so this is not normally visible. Two families that had never been registered in `runtime_identifiers.json` at all (grobda, domogram) are now covered by the single shared `ground` scope, closing that gap. The exact draw-priority hardware is abstracted behind the reference port's OSD sprite layer, so the arcade ordering is cited from the game's well-established rendering rather than a line-level source label.
