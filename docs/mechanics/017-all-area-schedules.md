# All normal area schedules — the 16-table ingest and the accelerated trace

- Mechanic: AREA-03 (present) — all 16 normal area object schedules are ingested into the scheduler's slice-5 representation, and an accelerated deterministic trace consumes every record of all 16 areas in order (continuing at area 7 after area 16) with no unknown record kind and no Super-only object. A data-drop only: the runtime consume/advance blocks (AREA-02, record 016) move no code.
- Derived behavior: Each of the 16 areas now carries its own object schedule. As an area scrolls, its own records fire in table order (the AREA-02 consume), and completing an area advances to the next, looping 16→7 with no win screen. No Super-Xevious table, row, or object type is present. The per-record effects (spawn, formation, difficulty, boss/secret masks) still arrive with the enemy slices; this mechanic is the completeness of the schedule *data* for every area and the ordered full-game loop over it.
- Reference provenance: `jotd666/xevious@71473685a8c7856c8401c8519276cd97a38d4183`; the 16 decoded normal tables `area_1_obj_tbl_normal` through `area_16_obj_tbl_normal` are committed in [docs/spec/data/area-schedules.json](../spec/data/area-schedules.json) (each area's `source.label` is the `_normal` extract), hash-guarded by [manifest.json](../spec/data/manifest.json); the record-kind vocabulary is the `schedule_action` field of [object-types.json](../spec/data/object-types.json); the 1–16→7 loop and the no-win-screen rule are the settled [area progression and terrain](../spec/area-progression-and-terrain.md) document. `tools/reference_extract.py` draws no byte from any `*_super` table and rejects object types above `NORMAL_TYPE_MAX` (0x57) at extraction, so the committed tables are normal-only by construction.
- Transfer class: Structured table (data) — no new behavior code this slice.
- Scratch interpretation: `_load_all_area_schedules` flattens all 16 areas' `_load_area_schedule(n)` outputs (each area = its records + one materialized sentinel row) into the same three FAITHFUL parallel Stage lists AREA-02 built — `schedule handler`, `schedule trigger row`, `schedule payload` (the opaque `object_type` + `params` JSON) — and sets the two 16-entry index lists `area schedule start`/`area schedule end` to each area's contiguous 1-based INCLUSIVE span into those columns (748 records + 16 sentinels = 764 entries). Areas are visited by explicit number (`range(AREA_FIRST, AREA_MAX + 1)`) after an up-front check that the data defines exactly areas `AREA_FIRST..AREA_MAX` once each, so a missing OR duplicated area fails loud with a clear message. The runtime consume/advance blocks (`_consume_schedule`, `_enter_area_top`, `_advance_area_number`, `install_advance_area`) index those lists by the live `area number` and are UNCHANGED — the whole slice moves no code path, which is exactly the seam AREA-02 was built to allow. The accelerated trace is a deterministic Python fixture OVER THE COMMITTED DATA — not the generated project, and not an execution of the Scratch consume blocks — i.e. a data-completeness simulation.
- Scratch evidence: `_load_all_area_schedules` in `tools/game_director.py`, and the flattened schedule/index Stage lists in `src/xevious/project.json`. Structural checks in `tests/test_scratch_project.py`: the generalized `_area02_failures` (three equal-length columns partitioned by the two index lists into contiguous 1-based per-area spans, each span ending in the materialized sentinel) with its interior-area `break_length`/`break_sentinel` negatives, and `test_generated_schedule_has_no_super_or_unknown_object` (every baked `schedule payload` decodes to `object_type <= NORMAL_TYPE_MAX` and a known handler; the sentinel is skipped). Lossless golden in `tests/test_spec_docs.py`: `test_all_area_schedules_round_trip_from_json` independently re-derives each area's span from the JSON record counts (stride = records + 1) and byte-checks each flattened window against the source records + its sentinel — the airtight catch for an offset off-by-one that would leak one area into the next. Accelerated trace in `tests/test_spec_docs.py`: `test_accelerated_full_game_trace_1_16_then_7` walks areas 1..16 then continues at 7, consuming every record and asserting every handler is known and every `object_type` is normal, with no area 17 and no win screen.
