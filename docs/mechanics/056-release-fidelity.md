- Derived behavior: (1) **add_object.** When the area clock reaches an add_object record's row, the record names an object type and one raw arcade object slot: 0x00 for the bonus flag (the ground band's slot 0), 0x3A or 0x3B for the single flyers (the first two formation slots). The arcade writes the type into that slot unconditionally; on the same frame the object pass gives the type its handler only if the slot was idle. If the slot was busy, the live object's handler keeps running and clears the type when that object frees, so the record is lost — never queued or retried. The new object's own init runs on the following frame: the flag takes the craft-excluding random column, hidden and worth 1,000 at reveal; Torkan, Kapi and Garu Zakato take the plain random column; Terrazi takes the craft-excluding one. Because the object pass runs before the formation spawner, a placed single owns its slot before the spawner looks for empty ones, and the spawner simply skips it while it lives. The Garu Zakato's detonation reads slot 0x3B absolutely and stamps the four Brag Sparios into 0x3C–0x3F.

- Scratch interpretation: **A one-tick register, then a placement step.** The schedule consumer's add_object branch checks the target's `slot type` at the moment the record fires — the arcade's pickup point — and, only if it is 0, writes `pending object type` and `pending object slot` (the raw slot plus one, the 1-based Scratch index). A busy slot leaves the register empty: the record is gone. The walk then calls the new warp proc `place pending object` after the walk and the bomb and before `spawn flying enemies`; it re-checks the slot is still empty, stamps the type through `walk type`, runs that type's EXISTING init (`INIT_TORKAN`, `INIT_KAPI`, `INIT_TERRAZI`, `INIT_GARU_ZAKATO`, or the flag seed now shared with the debug ground key), and clears the register every time. The flag seed was factored out of the debug-key path into one builder with no debug-key gate. A build guard (`_check_add_object_records`) refuses a schedule that names a type/slot the step cannot place, or two add_object records on one row in one area (the register holds one record per tick). `GARU_ZAKATO_SLOT` is now the second flying slot (0x3B); the debug Garu stamp uses it too.
